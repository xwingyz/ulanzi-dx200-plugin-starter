# PomoWave 提醒时长、背景音与按键交互设计

状态：已获用户口头批准，待书面复核

日期：2026-07-28
范围：`plugins/com.ulanzi.lexutility.ulanziPlugin` 的 `pomowave` action

## 1. 目标与边界

本次改动解决四类问题：

1. 等待用户手动开始下一阶段时，循环提示音默认最多播放 3 分钟，并可配置为持续、1 分钟、3 分钟、5 分钟或 10 分钟。
2. 长按重置当前工作后不自动开始倒计时。
3. 双击跳过双击开始前键面所显示的当前阶段。
4. 专注期间可播放本地循环背景音，并支持固定选择、每轮随机选择和音量调节。

只修改 PomoWave 业务模块、Property Inspector、中英语言包、音频资源、PomoWave 规格和专项测试。双击识别继续使用共享 `dispatchShortPress`，不修改共享按键基座。当前工作区其他 action 的未提交改动不在本次范围内。

## 2. 用户交互

### 2.1 提醒时长

Property Inspector 用单选设置替换原有“持续提示”布尔开关：

- 持续
- 1m
- 3m
- 5m
- 10m

默认值为 3m。该设置只控制下一阶段没有自动开始、PomoWave 停在 `awaiting` 时的循环提示。自动进入下一阶段时仍只播放一次提示音，避免与新阶段或专注背景音重叠。

有时限的循环提示到期后只停止声音，键面继续停在等待态。持续提醒直到用户确认、跳过、长按重置、Inspector 重置或实例销毁。

### 2.2 按键

- 单击保持现有语义：开始、暂停、恢复，或确认等待中的下一阶段。
- 长按停止提示音和背景音，保留已完成专注轮次，把当前工作重置为完整专注时长并停在未运行状态。键面显示完整专注时间和 `PAUSED`，再次单击才开始。
- 双击静默跳过双击开始前键面所显示的阶段：
  - 跳过专注仍计入一轮；
  - 跳过短休息或长休息不增加轮次；
  - 等待中的阶段也可跳过；
  - `idle` 没有可跳过阶段，保持 `idle`；
  - `done` 回到初始状态。

共享双击合同规定第一次短按必须立即执行。PomoWave 因此在 `onRun` 改变状态前保存阶段快照；第二次短按成立后，`onDoublePress` 依据该快照执行跳过，避免 `idle` 双击先启动再误算一轮，也避免 `awaiting` 先启动后跳错阶段。action 不自行识别双击。

### 2.3 专注背景音

背景音设置包括：

- 背景音：无声音、轻雨、壁炉、森林、海浪、咖啡馆、棕色噪声；
- 随机选择：关闭时使用固定选项，开启时每次进入新的专注轮次从六种声音中均匀随机选择；
- 背景音量：`0..100`，默认 `35`；
- 试听/停止试听：使用当前音量播放选中的声音，不改变计时状态。

背景音只在 `phase=focus && running=true` 时播放。休息、等待、暂停、完成、跳过和重置均停止或暂停背景音。

同一轮专注的随机结果保持稳定。暂停后恢复使用原声音，不重新抽取；插件重启后恢复运行中的专注，也继续使用该轮已保存的声音。播放器支持进程暂停/恢复时从原位置续播；平台能力不足时停止播放器，恢复专注时从循环起点重新播放。

## 3. 设置与运行态

### 3.1 设置字段

| 字段 | 默认值 | 合法值 | 含义 |
| --- | --- | --- | --- |
| `cueDuration` | `180` | `continuous` / `60` / `180` / `300` / `600` | `awaiting` 循环提醒的最长秒数 |
| `backgroundSound` | `rain` | `none` / `rain` / `fireplace` / `forest` / `ocean` / `cafe` / `brownNoise` | 固定背景音或关闭 |
| `backgroundRandom` | `false` | 字符串布尔值 | 每轮专注是否重新随机选择 |
| `backgroundVolume` | `35` | `0..100` 的数字字符串 | 背景音和背景音试听音量 |

`repeatManualCue` 从默认设置、归一化结果和 Inspector 提交字段中移除。旧持久化记录升级后使用新的默认 `cueDuration=180`，其他已有设置不变。未知的旧字段不会继续写回规范化设置。

### 3.2 运行态

PomoWave 运行态版本升级。除现有阶段、时钟和轮次字段外，新增：

- `selectedBackgroundSound`：当前专注轮次实际使用的背景音 key；
- 必要时保存能够判断该选择是否仍属于当前专注轮次的轻量标识。

播放器句柄、暂停状态、generation、试听状态、提醒开始时间和定时器句柄都是实例内临时状态，不写入持久化文件。

随机结果只在真正进入新一轮 `focus` 时生成。暂停、恢复、设置回读和进程恢复不得重新生成。用户在运行中的专注阶段修改固定声音、随机开关或音量时，当前实例立即按新设置重启背景播放器；开启随机后仅在需要生成当前选择时抽取一次。

## 4. 音频资源

资源统一放在：

```text

```

采用以下 CC0 候选源：

| key | 素材 | 来源 |
| --- | --- | --- |
| `rain` | Soft Rain Loop | https://freesound.org/s/595717/ |
| `fireplace` | Fireplace | https://freesound.org/people/myLoop/sounds/852107/ |
| `forest` | Forest birds - ambient seamless loop | https://freesound.org/people/Magnesus/sounds/723913/ |

| `brownNoise` | Brown Noise | https://freesound.org/people/tracyradio/sounds/737409/ |

所有候选页在设计时均明确标注 Creative Commons 0。实施时必须重新核对下载文件与对应页面，保存来源、作者、原文件名、许可证、下载日期和处理说明。

素材处理规则：

- 只做循环边界裁切、淡入淡出、响度统一和有损压缩；
- 不改变素材类别，不叠加来源不明的声音；
- 输出格式以 macOS 和 Windows 系统播放器均可可靠读取为准；
- 控制插件总体积，目标新增体积不超过 15 MB；
- 保留一份随插件分发的 `CREDITS.md` 或等价许可证清单。

## 5. 播放器与生命周期

提示音、背景音和试听使用三个相互隔离的实例通道。每个通道至少维护：

- 当前子进程句柄；
- generation；
- 播放/暂停标记；
- 对应的实例定时器槽。

generation 使被停止或替换的旧播放器回调失效，旧回调不得跨阶段、跨设置或跨试听重新排音。

背景音播放流程：

1. 进入运行中的专注时解析固定或随机声音。
2. 启动本地播放器并传入归一化音量。
3. 文件自然结束后，仅在实例仍为同一代、仍处于运行中的专注时重新播放。
4. 暂停专注时优先暂停播放器；无法暂停则停止。
5. 恢复专注时优先恢复原进程；原进程不存在则从循环起点重播同一声音。
6. 离开专注、跳过、重置、销毁或改选声音时停止旧进程并使其回调失效。

循环提醒流程：

1. 进入 `awaiting` 时记录提醒开始时间并播放第一声。
2. `cueDuration=continuous` 时持续循环。
3. 数值时长以提醒开始时间为基准；到达上限后不再排下一声。
4. 自动开始下一阶段时绕过循环逻辑，只播放一次。
5. 用户操作或实例销毁立即停止并清理。

macOS 使用系统播放器；Windows 使用系统媒体能力；其他平台尝试可用的本地播放器。播放器缺失、音频文件缺失、启动失败或异常退出时，只停止当前音频通道，计时状态机继续运行。背景音失败不把键面切到 `ERR`，下一轮或设置变化时允许重试。

## 6. Property Inspector 与多语言

Inspector 保持现有结构，新增“提醒时长”和“专注背景音”区域：

- 提醒时长使用分段按钮或下拉选择，不使用含义不清的复选框；
- 背景音可逐项选择，另设随机开关；
- 音量使用滑杆并显示当前百分比；
- 试听与停止试听使用明确按钮，不依赖选择动作隐式长时间播放；
- 手势说明改为“单击开始/暂停/恢复/确认；双击跳过当前阶段；长按重置但不开始”。

新增静态文案全部进入 `en.json` 与 `zh_CN.json`。使用独立的 `Background volume` 本地化键，避免与现有表示存储卷的 `Volume` 键发生语义冲突。

## 7. 测试与验收

专项测试至少覆盖：

- `cueDuration` 合法值、默认 3 分钟和非法值回退；
- 手动等待态的 1/3/5/10 分钟上限与持续提醒；
- 自动衔接只播放一次；
- 确认、跳过、长按、重置和销毁停止提醒；
- 长按后为完整专注时长、未运行且保留轮次；
- 双击使用第一次短按前的阶段快照；
- `idle`、运行中、暂停、`awaiting` 和 `done` 的双击边界；
- 跳过专注计入轮次，跳过休息不计入；
- 背景音仅在运行中的专注阶段播放；
- 固定选择、随机选择、每轮稳定、跨重启恢复和新轮重抽；
- 音量归一化、运行中改音量和改声音；
- 暂停/恢复、阶段切换、异常退出和销毁时的播放器清理；
- Inspector 提交、试听/停止试听和恢复默认；
- 中英语言包 key 对齐；
- 音频枚举、实际文件和许可证清单一致。

完成验证顺序：

1. 运行 PomoWave 专项测试和 Inspector 生命周期测试；
2. 运行仓库根目录 `npm test`；
3. 执行 `git diff --check`；
4. 从主检出执行 `npm run dev:desktop -- --plugin com.ulanzi.lexutility.ulanziPlugin --mode restart`；
5. 核对宿主副本与仓库音频及代码一致；
6. 在桌面宿主验证单击、双击、长按、提醒上限、随机背景音、音量、暂停恢复和设置回读；
7. 删除旧实例并重新拖放，验证 UUID 绑定与默认值。

实施完成时同步更新 `docs/specifications/actions/pomowave.md`，包括设置表、状态版本、按键语义、提示音生命周期、背景音资源、错误降级、测试项和“最后代码核对”日期。

## 8. 成本、风险与失效边界

实现成本主要在跨平台播放器生命周期、音频处理和状态恢复，预计高于普通 Inspector 字段改动。维护负担包括随插件保留许可证清单、确保音频资源被同步脚本完整复制，以及后续新增背景音时同步枚举、语言包、资源清单和测试。

主要风险：

- 系统播放器对暂停、恢复、音量或格式的能力不一致；
- 短音频由外部进程重复启动时可能出现轻微循环间隙；
- 咖啡馆等原始素材体积较大，需要压缩后再评估质量；
- 共享双击合同“第一次单击立即执行”要求业务快照正确，否则会跳错阶段；
- 音频素材页面或下载入口可能变化，实施时必须再次核对许可证和文件身份。

本设计在以下条件下失效，需要重新评估：

- Ulanzi 宿主禁止插件进程启动系统媒体播放器；
- Windows 目标环境缺少可用的系统媒体组件；
- 素材实际下载文件与页面标注不一致；
- 压缩到总体积目标后出现不可接受的循环接缝或音质下降；
- 真机证明长时间本地播放明显影响插件进程稳定性或其他 action。
